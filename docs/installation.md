# 安装、升级与数据恢复

适用版本：DSH Launcher 3.2.0 起的 Windows x64 发行版。

## 下载与安装

从 [本分支 Releases](https://github.com/ZhangYuanzheng1006/dsh-launcher/releases/latest) 下载 `DSH-Launcher-Setup-<版本>-x64.exe`。Release 同时提供可选的 Chrome Cookie Bridge ZIP 与 `SHA256SUMS.txt`，源码压缩包不是安装包。

安装要求：Windows 10/11 x64，建议 4 GB 以上内存；首次部署 DSH 时需要联网和额外磁盘空间。安装启动器无需预装 Node.js、pnpm 或开发工具。暂未提供其它系统和 CPU 架构的发行包。

双击安装 EXE，选择中文或英文，按向导安装。默认只安装到当前 Windows 用户下，无需管理员权限；可选择安装位置，默认创建桌面和开始菜单快捷方式。建议使用独立的程序文件夹，不要与用户会话、源码或运行环境目录混放。

发行包暂未代码签名，系统可能显示“未知发布者”。可用 PowerShell 核对文件哈希，并与同一 Release 的 `SHA256SUMS.txt` 对比：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath ".\DSH-Launcher-Setup-3.2.0-x64.exe"
```

## 第一次启动

1. 启动 DSH Launcher，打开「设置」，执行运行环境部署。
2. 程序联网下载便携 Node.js、pnpm 和官方 DSH 包，安装在配置的运行环境目录中；无需全局安装 Node。网络代理或镜像不可达时可在设置中检查路径和环境。
3. 部署成功后返回实例页，启动默认 DSH 实例。进入其 DSH 界面，填入自己的模型配置、API Key 和工作目录。
4. 需要多个版本时，在实例编辑中选择固定版本并安装，步骤见 [实例指南](instances.md)。

界面中沿用的“离线部署”名称指使用独立的本地运行环境；**首次下载依赖仍需要联网**。模型服务是否需要联网由你自己的配置决定。安装启动器、升级启动器和安装 DSH 运行环境是独立操作。

## 用新版 EXE 覆盖升级

1. 结束正在执行的任务，从启动器菜单或托盘选择退出，确认旧启动器已关闭。
2. 按下节备份用户资料。
3. 下载本分支的新版本安装 EXE，直接运行，沿用已登记的安装位置和当前用户范围，**无需先卸载**。
4. 安装器替换程序文件并更新快捷方式。启动后核对实例、资料、固定版本和配置。

安装向导欢迎页始终保留覆盖升级说明。安装器使用固定应用标识与 GUID 查找旧安装；后续发行必须保持这些值。安装器不会删除程序目录外的配置、Cookie、DSH_HOME 或运行环境。请勿手工把这些目录放入安装目录，否则它们可能被程序文件替换或卸载流程影响。

升级启动器不会自动升级 DSH 内核。共享运行环境通过应用内的运行环境更新操作升级；固定版本实例由各自的版本安装操作维护。跨 DSH 版本的数据和第三方插件兼容性仍需自行确认。

本分支沿用上游安装身份与配置目录，意在覆盖升级兼容安装；**上游和本分支不支持并排安装成两个独立产品**。从更老的上游版本迁移前请完整备份；本轮只对本分支安装流程做验收，不承诺所有历史配置都兼容。

## 数据在哪里，怎么备份

| 内容 | 默认位置 | 注意 |
| --- | --- | --- |
| 启动器配置、分组、浏览器资料与 Cookie | `%APPDATA%\dsh-launcher` | 主配置为 `launcher-config.json`；完整备份整个文件夹，包含默认和独立资料。 |
| DSH 会话、插件配置、凭据 | `%USERPROFILE%\.dsh` | 启动器设置、`DSH_HOME` 环境变量或实例独立 home 可改变位置。 |
| 共享与独立版本运行环境 | `%USERPROFILE%\.dsh-runtime` | 固定版本位于该目录内的 `instance-runtimes`，请按实际设置核对。 |
| 插件库 | `%USERPROFILE%\DSH-Plugin` | 设置可改变位置；本地插件还可能引用外部源码。 |
| 工作区、附件与下载文件 | 各实例工作目录和你选择的下载位置 | 不包含在启动器配置文件夹中，需单独备份。 |

备份时先退出启动器及其托管任务，再复制上述实际路径到一个带日期的新文件夹。不要公开上传备份：其中可能包含 API Key、Token、Cookie 和私有会话。恢复浏览器登录态时优先使用同一台机器、同一 Windows 用户；系统加密或站点风控可能使跨机器复制后的 Cookie 无效。

配置采用原子保存和有效备份；若主配置损坏，程序尝试恢复备份并保留损坏原件。不要为了排错直接删除整个 userData，也不要使用“清空资料”代替升级。

## 回退与卸载

遇到新版问题，先退出程序并保留现场备份，再安装之前的本分支 EXE。启动器配置格式可能随新版变化，**程序降级不等于配置回滚**：需要时一起恢复升级前的完整资料备份。旧版 DSH 也可能不认识新版会话格式，请使用独立 home 测试。

从 Windows「已安装的应用」卸载 DSH Launcher 会移除程序与快捷方式；本分支默认保留用户资料、DSH 数据与运行环境。需要彻底清理时，应在确认备份和实际路径后手工处理对应资料目录。不要删除仍被命令行 DSH 或其它实例共用的目录。

## 常见问题

- **安装器提示应用仍在运行**：从托盘退出，完成或停止任务后重试。不要反复强制结束其它应用来“清端口”。
- **应用能打开，DSH 启动失败**：检查是否完成运行环境部署、Node 路径、端口占用和实例日志；固定版本需要先安装对应精确版本。
- **升级后看不到原实例**：确认正在使用同一 Windows 用户与本分支安装，核对 `%APPDATA%\dsh-launcher` 和配置内自定义路径，优先恢复备份。
- **Google/Gemini 无法在内嵌窗口登录**：在 Chrome 中登录，再按 [扩展指南](../chrome-extension/README.md) 启用可选 Cookie Bridge；某些登录状态仍无法跨浏览器复用。
- **Chrome 扩展断开**：核对启动器是否已启用桥、端口与认证模式是否一致；固定 Token 需要粘贴当前值。
- **桌面应用嵌入异常**：退出嵌入并保留进程，在外部窗口继续使用；各应用版本和渲染方式不同，嵌入兼容性不是 Windows 通用保证。

反馈请到 [Issues](https://github.com/ZhangYuanzheng1006/dsh-launcher/issues)，附启动器版本、Windows 版本、复现步骤与已去除敏感信息的日志。不要提交完整配置、Cookie 或个人会话。
