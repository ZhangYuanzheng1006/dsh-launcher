# 实例与 DSH 运行版本隔离

## 三种实例

| 类型 | 用途 | 需要准备 |
| --- | --- | --- |
| DSH | 启动官方 DSH 并嵌入 Web UI | 共享运行环境或已安装的固定版本、可用端口、DSH_HOME。 |
| Web | 启动你自己的 Web 服务并打开页面 | 启动命令、工作目录、端口和健康检查路径。 |
| GUI | 管理本机已安装的桌面应用窗口 | 应用 EXE；部分应用支持发现、接管已有窗口和退出嵌入。 |

分组只改变实例和链接的可见性，不复制它们、不决定其 DSH_HOME，也不决定网页的登录资料。删除实例移除实例配置并停止相关托管状态，不删除工作目录或 DSH_HOME。

## 共享运行环境与固定版本

DSH 实例可选择两种运行方式：

- **继承共享环境**：沿用设置中的源码或内置运行环境。适合现有实例与日常使用；共享环境升级后，这些实例下次启动会使用更新后的版本。
- **固定版本**：指定已经发布的完整版本号，例如 `0.2.1-rc.2`。该实例拥有独立版本安装目录；启动服务和执行插件 CLI 使用同一份 DSH，不借用共享环境的 DSH 包。

固定版本只接受精确版本号，不接受 `latest`、`next`、`^0.2.1` 或路径。列表来自官方已发布版本；“格式有效”不代表 npm 上确实存在，安装失败时保留原有可用环境并显示错误。

## 创建或编辑固定版本实例

1. 在实例页新建 DSH 实例，或编辑已有 DSH 实例。
2. 选择固定运行版本，填写精确版本或从已发布版本列表选择。
3. 选择该实例**独占的 DSH_HOME**。固定版本实例不能和其它实例共享同一个 home，避免跨版本写入同一会话或插件配置。
4. 保存后安装所选运行版本，等待状态变为已安装，再启动实例。
5. 在实例卡查看选定版本、安装状态和实际运行状态。插件安装与启停操作会经过事务与占用检查，避免运行中替换环境。

更换固定版本前先停止实例。固定版本目录位于配置的 `runtimeRoot/instance-runtimes/<实例标识>/<精确版本>`，旧版本目录不会被共享运行环境更新覆盖。Node.js 运行环境仍是共享的，因此这是 **DSH 包与数据目录隔离**，不是虚拟机或操作系统沙箱。

## 数据与插件兼容

指定独立 DSH_HOME 不会自动复制旧会话、凭据或插件。请先备份，在目标 home 中重新配置，或在确认 DSH 格式兼容后显式迁移。不要为了“复用登录”把多个版本强行指向同一 home。

插件依赖宿主版本、声明方式与 native 模块；固定 DSH 版本不能保证所有第三方插件都兼容。插件库可以保存源码，但各 profile 的依赖和本地插件快照按实例运行环境准备。排错时记录 DSH 精确版本、插件版本和启动日志。

旧实例没有 `runtimeVersion` 时默认继承共享环境，避免升级启动器时自动迁移生产数据。共享运行环境的更新不会替换固定版本实例；不要把“启动器版本”“共享 DSH 版本”“实例固定 DSH 版本”混为一项。

## 网页资料和 Chrome Cookie Bridge

网页链接可以选择默认资料或独立的持久资料；默认资料沿用 Electron 的 `defaultSession`，保存历史登录态。Chrome 资料扫描只读取 Chrome 的资料名称和标识，不解密或直接写入 Chrome Cookie 数据库。

Cookie Bridge 是可选的单向 Chrome → Launcher Cookie 同步，目标固定为默认资料。它不迁移 localStorage、IndexedDB 或完整浏览器配置，也不构成通用 Google 登录绕过方案。详见 [扩展指南](../chrome-extension/README.md)。
